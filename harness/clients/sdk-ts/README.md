# `@orrery/client`

The TypeScript half of the client SDK: `AguiSession` (decode, `seq`, re-attach `since`,
control RPC) and `SurfaceStore`. **Pure data, no drawing** — exactly the same two things
[`../sdk-rs`](../sdk-rs) gives Rust, built on stock `@ag-ui/client`'s `HttpAgent` over SSE.

Types come from [`@orrery/protocol`](../../protocol), which is generated by
`cargo xtask typegen` and must not be hand-edited.

```bash
pnpm -C harness/clients/sdk-ts test   # vitest, over ../conformance
```

It passes the shared fixtures in [`../conformance`](../conformance) — the same files
`orrery-client` runs in Rust, asserted the same way. If the two ever disagree, one of the
five clients is drawing something the others are not.

## The session is stock `@ag-ui/client`

`AguiSession` wraps `HttpAgent` and hands it back unmodified through `httpAgent()`. That
*is* the "existing AG-UI clients work unmodified" proof: if this package had to patch the
agent, the claim would be false. What it adds is the half AG-UI has no vocabulary for —
`session.attach(since)`, `turn.cancel`, `intent`, `consent.answer`, `query` — over a small
`fetch` client against `POST /control`.

`run()` parses the SSE stream itself rather than going through the agent's subscriber API,
for one reason: our frames carry a `seq` the stock agent drops, and `seq` is the whole of
the resumption story.

## A client never writes state

AG-UI's shared state is bidirectional by design; ours is not. `StateSnapshot` and
`StateDelta` flow outward only, and an edit a person makes arrives back as an `intent` the
kernel validates. Anyone porting a component that expects to write state directly needs to
know that.
